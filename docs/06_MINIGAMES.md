# Пять мини-игр
## Общий контракт
src/minigames/{potions,duel,stealth,quidditch,parchment}.js: run(container,params) → Promise<{ok,score,details}>. score целое0..100. params и отмена по03; details={reason:completed/failed/skipped,elapsedMs,...}. Повтор/пропуск — системный UI engine, не реплика. Одно разрешение Promise, очистка RAF/listeners/capture при выходе. Pause при visibilitychange; время паузы не учитывается.
Canvas896×1200, DPR≤2. Координаты pointer переводить через фактический boundingClientRect. Touch/mouse одинаковы. Все кнопки44px, hit zones минимум56px. DebugAutoWin завершается после первого RAF, не меняет правила обычной игры.
## Potions — scene03 D295
Состояния book→ingredients→stir→qte→roundResult→следующий рецепт→complete. Два раунда фиксированно recipe01,recipe02. Книга20 рецептов; страница один рецепт, стрелки/свайп, поиск по имени и ингредиентам без регистра; поиск не меняет назначенный рецепт. Панель книги можно открыть до QTE, пауза времени.
Три правильных ингредиента переносить в круг котла центр448,700 r160; порядок свободный. Неправильный ингредиент возвращается, до3 ошибок на раунд; третья — failed. Выбор из6 карточек (3 нужных+3 следующих по циклу из общего списка).
Stir8s: шкала0..1, старт.5, зелёная зона.25..75; удержание поднимает .18/s, отпускание опускает .12/s; нужно≥4.5s суммарно в зелёной зоне. Один pointer.
QTE бегунок0..1 с отражением, .35/s, зелёная зона.32..68; окно попытки8s, один тап. Попадание успех; промах failed.
qteAccuracy=clamp(1-abs(позиция-.5)/.18,0,1). score среднее двух раундов: round=round(70×greenTime/8+30×qteAccuracy), clamp0..100. После failure engine retry всего эпизода либо skip ok:true; сюжетных флагов нет.
Canvas: котёл Bézier, жидкость эллипс, пузырьки20, карточки с текстом и простыми силуэтами растений/порошков/перьев; внешних предметных картинок не нужно.
Приёмка: все20 рецептов находятся поиском; recipe01/02 выполнимы одной рукой; пропуск и повтор не теряют сюжетный узел.
## Duel — scene04 D407 / scene06 D627
Состояния telegraph→select→trace→resolve→следующий ход→end. HP игрока/противника100; максимум5 ходов. Верхняя полоса заклинания противника, справа три кнопки, поле росчерка x80..640,y420..900.
Противник циклом Expelliarmus/Stupefy/Petrificus. Контрвыбор соответственно Protego/Expelliarmus/Finite. Это фиксированная игровая таблица, не утверждение канонической механики.
На выбор6s, на trace5s. Траектории в нормализованном квадрате: Protego [(0.1,.8),(.5,.1),(.9,.8)]; Expelliarmus [(.1,.2),(.5,.8),(.9,.2)]; Finite [(.1,.5),(.4,.2),(.6,.8),(.9,.5)].
Resample жеста в64 точки; ошибка — средняя дистанция до соответствующей точки/диагональ поля. accuracy=clamp(1-error/.15). speed=clamp(1-elapsed/5000). Правильный выбор: damage=round(20+20×accuracy+10×speed), входящий урон round(15×(1-accuracy)). Неправильный/таймаут: damage0, входящий30. Точки нельзя пропускать одним тапом: длина жеста≥60% контура.
Сц4 ok=HP врага≤0 либо на5м ходу HP игрока>HP врага; ничья поражение. Engine пишет duelScene4Win и выбирает D408/D437. Повтор не обязателен: поражение — полноценный сюжетный исход.
Сц6 всегда ok:true, даже HP0; details.practiceFailed хранит фактический результат, score фактический. Engine не переводит в госпиталь.
Рисование: линии контуров, лучи, вспышки, частицы≤50; персонажи из manifest. Приёмка: проверить обе ветви4 и гарантированный успех6.
## Stealth — scene05 D570
Карта896×1200, игрок круг r18 в(448,1100), выход(448,80), скорость140px/s. Drag задаёт цель, отпускание останавливает. Стены x0..80 и816..896. Укрытия прямоугольники (80,760,130,150) и(686,360,130,150).
Два стража (Снейп/староста) в(310,730)/(590,330), конус длиной260,угол55°, вращение±55° за4s/5s. Игрок в укрытии невидим; вне укрытия нахождение в конусе≥.6s теряет сердце. Старт5 сердец; возврат к последнему укрытию, invulnerability1.5s; попытка не расходуется при сворачивании.
Состояния ready→moving/hidden→caught→respawn→won/lost. score=20×оставшиеся сердца. Нет общего таймера.
Фон bg_corridor_night; конусы/ниши/сердца Canvas, староста силуэт, Снейп существующий спрайт. Ниши — игровая схема поверх фона, не обещание совпадения с архитектурой изображения.
0сердец → D571–575 → UI retry/skip; skip выставляет stealthScene5Win=true → D577; retry запускает5 сердец. Приёмка: все5 потерь, безопасное укрытие, успех без таймера, корректный skip.
## Quidditch — scene06 D656
**M5-upgrade (заказ владельца 16.11.2026) заменяет правила ниже: FSM ready→flight→snitch_chase→snitch_qte→result.** flight: 9 колец (r65, каждые 2.4s, y=260/600/900), бладжеры с 5s, игроки соперника с 10s; переход к снитчу при 6 кольцах либо через 22.5s (половина 45s). snitch_chase: свободный полёт по x110..800/y160..1040 (≤560px/s), Снитч r14 мечется и уворачивается; поимка = swept-касание или удержание ≤130px 2.2s; лимит 30s; бладжеры (каждые 3.4s) и охотники соперника (каждые 4.2s, часть подрезает по y) отнимают сердце. snitch_qte: шкала хватки 0..1 (старт .25), тап на бит (период .42s) +.10, мимо бита +.06, при простое >.18s падение .35/s; 0 или 14s — Снитч вырывается: −10 очков и новый заход (максимум 2 повтора, затем проигрыш). ok = Снитч пойман и сердца>0; score = 30×кольца/9 + 50 (Снитч) + 20×сердца/3 − 10×побеги, 0..100. retry/skip — системное окно engine, без изменений. Пауза по visibilitychange/blur, pointercancel не ломает управление. Кнопки DEBUG (→Погоня, →QTE, победа, проигрыш) только при ?debug=1.
Исходные числа фазы колец: ready→flight→result. Полёт45s; игрок x180,y600,r24, y ограничен160..1040. Палец управляет y, максимальная скорость500px/s, smoothing120ms. Мир движется справа налево180px/s.
Кольца r65 каждые3s, y=260/600/900 циклом; всего15. Бладжеры r25 каждые5s, y=900/260/600 циклом, скорость220px/s. Первые5s без бладжера. Столкновение:1сердце, invulnerability1.5s;3сердца.
ok:≥8 колец и сердца>0 к45s; иначе retry/skip engine. score=round(100×кольца/15). Кольцо засчитывается один раз при пересечении центра; столкновение проверять swept segment, не только конечную позицию кадра.
Метла/кольца/бладжеры Canvas, фон bg_quidditch; никаких отдельных новых артов. После lake повторно использовать этот же эпизод, затем choice06_02 без D665–668.
Приёмка: достижимые8 колец, корректное управление mouse/touch, пропуск с ok:true, один запуск на маршрут.
## Parchment — scene10 D978
Ресурсы bg_parchment_clean, magic_wand; текст импорт FINAL_LOVE_LETTER_TEXT. ready→dragging→revealing→complete. Палочка в правой панели с hit target64×64 независимо от тонкости картинки.
Область листа в координатах896×1200: x220..665,y340..910; перед выпуском сверить маску с чистым фоном. Текст18px CSS, layout внутри области; длинное финальное письмо разбивать на страницы, не уменьшать шрифт ниже16px.
Pointer path кисть r38 открывает grid32×48, учитывать только клетки внутри листа. На85% покрытия плавно открыть остаток за600ms, затем кнопка Завершить. Нет проигрыша/таймера. score=100. Искры≤50,ttl600ms; палочка следует pointer с pivot рукояти[.05,.5].
При reduced-motion показывать текст полосами без частиц; движение всё ещё открывает. Кнопка "Показать письмо" доступна сразу, details.reason=skipped. Engine завершает новеллу один раз.
